## 1. Executive Summary

### 1.1 Overall Architecture Status & Maturity
Udyam PAY has a well-structured modular-monolith backend core (Express 5.1, TypeScript strict mode, Prisma 6 + PostgreSQL 16 schema, `AppStores` persistence abstraction, integer-paise `BigInt` money math, Argon2id password hashing with scrypt fallback, HS256 JWT + refresh-token family reuse detection, 15-state application state machine, fail-closed `ProductionDisabledLenderAdapter`, circuit breaker, and append-only ledger guards) paired with an honest React + TypeScript + Vite frontend (`31` typed API wrappers mapped `1:1` to real Express routes, with zero invented endpoints and transparent `BackendRequiredNotice` placeholders for unbuilt modules).

However, **runtime wiring, tenant isolation, concurrency safety, and operational hardening lag significantly behind the architectural blueprint**:
1. Several critical security/lifecycle modules are implemented and tested in isolation yet left disconnected or broken in runtime wiring (`GET /auth/me` unauthenticated, `requireMerchantStatus` never mounted, `ExpirationWorker` never started, `CheckoutService.consumeSession` / `revokeSession` uncalled, `CommissionService.accrue()` bypassed, and `WebhookService` using an in-memory map absent on `PrismaStore`).
2. Cross-layer inspection uncovered **newly identified P0/P1 defects** not caught by prior reports: cross-merchant IDOR vulnerabilities on consent revocation and offer acceptance, missing shop/customer ownership checks on `POST /purchases`, parallel `DISCOVERY` mode falsely tripping lender circuit breakers via optimistic-lock collisions, webhook replay timestamp bypass and `RECEIVED` retry lockup, non-atomic `PrismaStore` concurrency/session updates, frontend paise truncation in the wizard, and a failing `518`-error backend ESLint baseline.
3. All external lending, KYC, e-Sign, e-Mandate, disbursement settlement, and utility BBPS flows are either simulated via local JSON fixtures (`JsonMockLenderAdapter`) or unimplemented placeholders.

### 1.3 Biggest Risks & Main Production Blockers
1. **Tenant Isolation / IDOR Gaps:** [`DELETE /api/v1/customers/:id/consents/:consentId`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/customers/customer.routes.ts#L73-L82), [`POST /api/v1/applications/:id/offers/:offerId/accept`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/offers/offer.routes.ts#L26-L33), [`POST /api/v1/purchases`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/purchases/purchase.routes.ts#L29-L48), and nullable-`merchantId` paths on application routes allow cross-tenant data access or tampering.
2. **Broken PostgreSQL Webhook & Financial Atomicity Path:** [`WebhookService`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/webhooks/webhook.service.ts) cannot resolve `externalReference` on `PrismaStore`, skips replay checks when `X-Lender-Timestamp` is omitted, permanently locks failed webhooks in `RECEIVED` state, hardcodes `150n/10000n` commission outside `CommissionService.accrue()`, and executes disbursement/transaction/commission writes without an enclosing database `$transaction`.
3. **Unenforced Merchant Verification & RBAC Drift:** [`requireMerchantStatus`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/auth/auth.middleware.ts#L75) is unmounted (allowing `PENDING_VERIFICATION` / `SUSPENDED` merchants to transact), while application/offer routes diverge on `SYSTEM_ADMIN` and `OPS_AGENT` roles.
4. **Concurrency & Discovery Orchestration Bugs:** [`WaterfallOrchestrator.executeDiscoveryMode`](file:///c:/Users/NANDINI%20PATEL/OneDrive/Desktop/udhyam-pay-backend/src/modules/orchestration/waterfall.ts#L247-L334) mutates shared state concurrently, causing `ConflictError`s that falsely trip healthy lender circuit breakers; `PrismaStore` `updateStatus` and `rotateSession` rely on JS read-then-write rather than atomic CAS `WHERE` predicates.
5. **External Provider, KYC & Regulatory Readiness Gap:** Zero live aggregator/NBFC APIs, zero encrypted PII/CKYC/DigiLocker/AA/penny-drop/e-Sign/e-mandate pipelines, no DPDP consent/erasure governance UI or safe retention-gated anonymization workflow, and no BBPS utility backend.

## 3. Consolidated Issue Register

*(Deduplicated and grouped into the 10 mandated domains, cross-referencing IDs in Section 2.2.)*

### 3.1 Critical Security
- **Cross-Merchant IDORs (F-001, F-002, F-003):** `DELETE /customers/:id/consents/:consentId`, `POST /applications/:id/offers/:offerId/accept`, and `POST /purchases` (`shopId`, `customerId`) fail to validate tenant ownership across linked entities.
- **Unauthenticated `/auth/me` & Nullable `merchantId` RBAC Bypass (F-004, F-010):** `GET /api/v1/auth/me` sits before `authMiddleware`; `application.routes.ts` & `offer.routes.ts` check `role === 'ADMIN'` only and let `if (merchantId && app.merchantId !== merchantId)` pass silently if a non-admin user ever has `merchantId: null`.
- **Unmounted `requireMerchantStatus` Guard (F-005):** `PENDING_VERIFICATION` and `SUSPENDED` merchants are not blocked server-side from creating purchases, checkout sessions, or loan applications.
- **Role Granularity & Auth Abuse Protections (F-011, F-019):** Zero permission differentiation between `MERCHANT_OWNER` and `MERCHANT_STAFF`; `logout` does not revoke active JWTs via `tokenVersion`; no route-specific brute-force limits on `/login`, `/register`, or `/checkout/sessions/:token`; `rotateSession` lacks atomic conditional update against concurrent refresh reuse.
- **Browser Token Storage Risk (F-023):** Frontend holds refresh tokens in `sessionStorage` until backend migrates to `HttpOnly` cookie rotation with CORS credentials.

### 3.2 Financial Correctness
- **Non-Atomic Disbursement / Commission Accrual & Bypassed Guard (F-009):** `WebhookService` mutates disbursement status, `FinancingApplication` (multiple state hops), `Transaction`, and direct `stores.commissions.accrue` outside any DB `$transaction`, hardcodes `150n/10000n` commission rate, skips `disbursements.record` when `externalRef` is absent, and bypasses `CommissionService.accrue()`'s `CONFIRMED` check.
- **Fractional Paise Truncation in Frontend Wizard (F-020):** `FinancingWizardPage` computes `(toPaiseBigInt(created.amountPaise) / 100n).toString()`, silently losing sub-rupee paise on non-whole amounts.
- **Missing Down-Payment + Principal Ceiling Check (AUD-OLD-4, F-015):** `ApplicationService.createApplication` validates `requestedAmountPaise <= purchase.amountPaise` instead of `requestedAmountPaise + downPaymentPaise <= purchase.amountPaise`.
- **EMI Float Multiplication & Discarded Amortization Schedule (F-017):** `EmiCalculator` casts `BigInt` paise to JS `Number` for intermediate reducing-balance multiplication; `ResultApplier` discards computed schedules (`repaymentSchedule: null`).
- **Missing Refund / Settlement / Commission Adjustment Flows (F-009, SEC-LEDGER):** Schema enums `TransactionType.{PURCHASE_PAYMENT, MERCHANT_SETTLEMENT, REFUND}` and `CommissionEntryType.ADJUSTMENT`, plus `CommissionService.reverse()`, have zero HTTP endpoints or settlement reconciliation workflows; `CommissionService.accrue()` also writes `amountPaise` vs `Transaction` without checking if net settlement/subvention rules vary by lender.
- **Database Ledger Hardening Gaps (AUD-OLD-5, AUD-OLD-6):** `Transaction` nullable unique constraint (`lenderId, lenderTransactionRef, type`) lacks `NULLS NOT DISTINCT`; append-only triggers do not guard against `TRUNCATE`.

### 3.3 Business Logic
- **Discovery Waterfall False Circuit-Breaker Trips (F-012):** Parallel discovery calls reuse stale `application` / `version`, causing the 2nd offering lender's `ResultApplier.apply()` to hit `ConflictError` and falsely increment `breaker.recordFailure()`. Config fields (`fallbackOnDecline`, `maxSafeRetries`, `routingRules`) remain ignored.
- **Non-Atomic Optimistic Concurrency & Offer Acceptance (F-013):** `PrismaStore.applications.updateStatus` validates `version` in JS before updating by `{ where: { id } }`; `OfferService.acceptOffer` splits offer status update, superseding other offers, and application transition across 3 separate queries; concurrent accept + cancel + expiration races lack DB lock isolation.
- **Application Cancellation Incomplete (F-015):** Leaves `ACTIVE` offers open (`OfferStatus.WITHDRAWN` unused) and never notifies `LenderAdapter.cancelApplication`.
- **Checkout Session Lifecycle Unused (F-016):** `CheckoutService.consumeSession` and `revokeSession` have `0` runtime callers, leaving QR checkout tokens unconsumed after financing initiation and unrevocable by merchants.
- **Broken Frontend Idempotency on Retry (F-021):** `MerchantPurchasesPage` regenerates `idempotencyKey` per mutation click; `submitApplication` and `acceptOffer` omit idempotency protection.

### 3.4 Backend Runtime Wiring
- **`WebhookService` In-Memory-Only Map (F-006):** `(this.stores as any).lenderApplicationsMap?.values()` fails silently on PostgreSQL (`PrismaStore`), breaking webhook-driven `externalReference` reconciliation.
- **`ExpirationWorker` Unwired (F-016):** Background sweeper exists and passes unit checks, yet `src/server.ts` never starts it.
- **`GET /api/v1/auth/me` Router Order (F-010):** Mounted before `authMiddleware`.
- **`PUT /api/v1/admin/lenders/:id/config` Unvalidated Body (F-014):** Missing Zod schema & `BigInt` string coercion; `GET /admin/audit-logs` ignores pagination query params; `GET /ledger/commission` passes unvalidated `parseInt`.
- **Untapped Verified Persistence Stores (`stores.ts`):** `merchants.list`, `users.listUsers`, `consents.listByCustomer`, `lenderApplications.listByApplication`, `transactions.findByApplication`, `disbursements.listByLenderApp`, `customers.anonymizeCustomer` have zero HTTP handlers.

### 3.5 Frontend/Backend Integration
- **Hidden RBI/KFS Terms & Unmasked Phones (F-024):** `OfferCard` omits `downPaymentPaise`, `aprPercent`, `taxesPaise`, `otherChargesPaise`, `termsVersion`, `termsUrl`, `expiresAt`, `repaymentSchedule`; `maskPhone` sits unused while detail pages render full customer phone numbers.

- **Missing Customer Self-Service QR & BBPS Utility Flows (F-024):** `CheckoutScanPage`, `KycPrimitives` uploads, and `UtilitiesPage` await backend OTP/session-submit/KYC/BBPS APIs (`BackendRequiredNotice`).

### 3.7 Privacy/Compliance (DPDP & RBI Digital Lending Context)
